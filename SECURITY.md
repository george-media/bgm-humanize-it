# Security and private material

These are instruction-only skills. They contain no credential store, external detector integration or runtime server. Text and files you supply are still processed by your chosen Codex host and any separately authorised tools under that host's policies.

Keep credentials, client records and identifiable drafts out of issues, pull requests and contributed examples. Use synthetic material to reproduce editorial problems.

If a problem exposes private data or enables unintended actions, do not include exploitation details or secrets in a public issue. Use GitHub's **Report a vulnerability** option if the repository offers it; otherwise arrange a private reporting channel with the repository owner before sharing sensitive details. This repository does not promise a monitored security mailbox or response deadline.

Ordinary writing defects belong in the [bug-report template](.github/ISSUE_TEMPLATE/bug_report.md). Include the host/version and a safe minimal example.
